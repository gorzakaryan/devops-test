1. Image-ների հետ աշխատանք
   Image-ը ձեր հավելվածի «նախագիծն» է (blueprint)։

**docker pull <image_name>** – Ներբեռնում է image-ը Docker Hub-ից։
**docker images** – Ցուցադրում է համակարգչում առկա բոլոր image-ները։
**docker build -t <name>** . – Ստեղծում է նոր image տվյալ թղթապանակում եղած Dockerfile-ի հիման վրա։
**docker rmi <image_id>** – Հեռացնում է նշված image-ը։

2. Container-ների կառավարում
   Container-ը image-ի աշխատող օրինակն է։
**docker run <image_name>** – Ստեղծում և միացնում է նոր կոնտեյներ։
-d – Աշխատեցնել հետին պլանում (detached mode):
-p 8080:80 – Միացնել համակարգչի 8080 պորտը կոնտեյների 80 պորտին։
--name <name> – Անուն տալ կոնտեյներին։

**docker ps** – Ցույց է տալիս միայն աշխատող կոնտեյներները։
**docker ps -a** – Ցույց է տալիս բոլոր (նաև կանգնեցված) կոնտեյներները։
**docker stop <container_id>** – Կանգնեցնում է աշխատող կոնտեյները։
**docker start <container_id>** – Նորից միացնում է կանգնեցված կոնտեյները։
**docker rm <container_id>** – Հեռացնում է կոնտեյները։

3. Ինսպեկցիա և Լոգեր
   Օգտակար են խնդիրները գտնելու (debugging) համար։
**docker logs <container_id>** – Տեսնել կոնտեյների ելքային տվյալները (output/logs)։
**docker exec -it <container_id> bash** – Մտնել աշխատող կոնտեյների ներս (terminal)։
**docker inspect <container_id>** – Ստանալ մանրամասն տեղեկություն կոնտեյների մասին (IP հասցե, կարգավորումներ)։

4. Docker Compose V2 (Ամենակարևոր փոփոխությունը)
   V2-ում հրամանները դարձել են ավելի ստանդարտացված:
**docker compose up** – Միացնում է նախագիծը (այլևս պետք չէ գրել docker-compose):
**docker compose up -d** – Աշխատեցնում է կոնտեյներները հետին պլանում:
**docker compose build --no-cache** – Վերակառուցում է image-ները թարմ վիճակում:
**docker compose cp** – Թույլ է տալիս ֆայլեր պատճենել տեղային համակարգչից դեպի կոնտեյներ և հակառակը (նորույթ V2-ում):
**docker compose watch** – (V2.20+) Ավտոմատ թարմացնում է կոնտեյները, երբ դուք փոփոխություն եք անում կոդի մեջ (շատ հարմար է ծրագրավորման ընթացքում):
**docker compose up -d --scale course=3**
   
5. Ռեսուրսների և Կոնտեյներների կառավարում
   docker stats – Իրական ժամանակում ցույց է տալիս, թե որքան CPU և RAM են օգտագործում ձեր կոնտեյներները:
**docker top <container_id>** – Ցույց է տալիս կոնտեյների ներսում աշխատող պրոցեսները:
**docker wait <container_id>** – Սպասում է մինչև կոնտեյները կանգնի և վերադարձնում է exit code-ը:

6. Docker Context (Աշխատանք տարբեր միջավայրերի հետ)
   V2-ում ավելի հեշտ է դարձել կառավարել հեռակա սերվերները հենց ձեր համակարգչից:
**docker context ls** – Ցույց է տալիս հասանելի միջավայրերը (տեղային կամ հեռակա սերվեր):
**docker context use <context_name>** – Միանգամից փոխում է աշխատանքային միջավայրը (օրինակ՝ ձեր համակարգչից կառավարել Cloud սերվերը):

7. Ընդլայնված մաքրում (Cleanup)
   docker image prune -a – Հեռացնում է բոլոր image-ները, որոնք այս պահին կոնտեյների կողմից չեն օգտագործվում (ազատում է հսկայական տեղ):
**docker compose down -v** – Կանգնեցնում է կոնտեյներները և ջնջում նաև տվյալների բազաները (volumes):

8. Մաքրման հրամաններ
   Docker-ը ժամանակի ընթացքում կարող է զբաղեցնել շատ տեղ սկավառակի վրա։
**docker system prune** – Հեռացնում է բոլոր չօգտագործվող կոնտեյներները, ցանցերը և ժամանակավոր ֆայլերը։
**docker volume ls** – Տեսնել տվյալների պահպանման բոլոր ծավալները (volumes)։

Հուշում: Եթե նոր եք սկսում, ամենից հաճախ օգտագործելու եք docker-compose up --build հրամանը, որը միաժամանակ թարմացնում է կոդը և միացնում նախագիծը։

8.1. Ջնջել ԲՈԼՈՐ կոնտեյներները (նաև աշխատողները)
   Սա ամենատարածված հրամանն է, որը նախ կանգնեցնում է, ապա հեռացնում ամեն ինչ.
**docker rm -f $(docker ps -aq)**
**docker ps -aq** – Վերադարձնում է բոլոր կոնտեյներների ID-ները:
-f (force) – Ստիպողաբար ջնջում է նույնիսկ աշխատող կոնտեյներները:

8.2. Ջնջել միայն կանգնեցված կոնտեյներները
   Եթե ցանկանում եք մաքրել համակարգը՝ առանց աշխատող պրոցեսներին դիպչելու.
**docker container prune**

Docker-ը ձեզնից հաստատում կհարցնի (y/n)։ Եթե ցանկանում եք հաստատումը շրջանցել, ավելացրեք -f դրոշակը:

8.3. Docker V2-ի առավելությունը (Compose)
   Եթե դուք կոնտեյներները միացրել եք docker compose-ով, ապա տվյալ նախագծի բոլոր կոնտեյներները ջնջելու ճիշտ ձևը հետևյալն է (գտնվելով նախագծի թղթապանակում).
**docker compose down**

Իսկ եթե ցանկանում եք ջնջել նաև Image-ները և Volume-ները (տվյալները).
**docker compose down --rmi all -v**

⚠️ Կարևոր զգուշացում
Կոնտեյներները ջնջելիս դրանց մեջ եղած բոլոր ժամանակավոր տվյալները կորչում են։ Եթե ունեք կարևոր տվյալներ տվյալների բազայում (PostgreSQL, MySQL և այլն), համոզվեք, որ օգտագործում եք Volumes, այլապես դրանք ևս կջնջվեն։

Հուշում: Եթե ձեր նպատակը սկավառակի վրա տեղ ազատելն է, ապա կոնտեյներներից բացի խորհուրդ եմ տալիս ջնջել նաև չօգտագործվող image-ները.
**docker image prune -a**

10. Docker Network (Ցանցային կապեր)
   Կոնտեյներները պետք է կարողանան խոսել միմյանց հետ։ Օրինակ՝ քո Backend-ը պետք է տեսնի Տվյալների բազան (DB)։
**docker network ls** – Ցույց է տալիս բոլոր ստեղծված ցանցերը։
**docker network create <name>** – Ստեղծում է նոր վիրտուալ ցանց (սովորաբար օգտագործվում է bridge տիպը)։
**docker network connect <network_name> <container_id>** – Աշխատող կոնտեյները միացնում է նշված ցանցին։
**docker network inspect <network_name>** – Ցույց է տալիս, թե որ կոնտեյներներն են միացված տվյալ ցանցին և ինչ IP հասցեներ ունեն։

11. Docker Volume (Տվյալների պահպանում)
   Երբ կոնտեյները ջնջվում է, նրա ներսի տվյալները կորում են։ Volume-ները թույլ են տալիս պահպանել տվյալները (օրինակ՝ DB-ի ֆայլերը) համակարգչի սկավառակի վրա։
**docker volume ls** – Ցուցադրում է բոլոր volume-ները։
**docker volume create <name>** – Ստեղծում է նոր տվյալների պահոց։
**docker volume inspect <name>** – Ցույց է տալիս, թե կոնկրետ որտեղ է պահվում ինֆորմացիան քո սկավառակի վրա (Mountpoint)։
**docker volume prune** – Ջնջում է բոլոր այն volume-ները, որոնք այս պահին ոչ մի կոնտեյների միացված չեն։

12. Debugging և Monitoring (Խնդիրների որոնում)
   Երբ ինչ-որ բան այն չէ, այս հրամանները փրկում են իրավիճակը.
**docker diff <container_id>** – Ցույց է տալիս, թե ինչ ֆայլեր են փոփոխվել կոնտեյների ներսում այն պահից սկսած, երբ նա միացել է։
**docker events** – Իրական ժամանակում ցույց է տալիս, թե ինչ է կատարվում Docker engine-ի հետ (օրինակ՝ երբ է կոնտեյները կանգնել կամ սկսել աշխատել)։
**docker top <container_id>** – Ցույց է տալիս կոնտեյների ներսում աշխատող պրոցեսները (ինչպես Linux-ի top հրամանը)։

13. Ֆայլերի հետ աշխատանք
**docker cp <src_path> <container_id>:<dest_path>** – Ֆայլ պատճենել քո համակարգչից կոնտեյների մեջ։
**docker cp <container_id>:<src_path> <dest_path>** – Ֆայլը կոնտեյներից հանել քո համակարգչի մեջ։

14. Image-ների արտահանում (Export/Import)
   Եթե ցանկանում ես image-ը տալ ընկերոջդ առանց Docker Hub-ի.
**docker save -o <file_name>.tar <image_name>** – Պահպանում է image-ը որպես .tar ֆայլ։
**docker load -i <file_name>.tar** – Վերականգնում է image-ը .tar ֆայլից։

Մի օգտակար «տրյուկ» (Alias)
Եթե հաճախ ես օգտագործում Docker, կարող ես քո տերմինալում ավելացնել այս հրամանը, որը կմաքրի բացարձակապես ամեն ինչ (կոնտեյներներ, image-ներ, ցանցեր), ինչն օգտագործված չէ.

**docker system prune -a --volumes**
